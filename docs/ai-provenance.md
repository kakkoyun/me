# AI provenance checks

`scripts/check-ai-provenance.sh` blocks undisclosed AI-generated content from
merging. It runs in `make test`, which `lint.yml` runs on every pull request, and
on its own via `make provenance`.

This document is mostly about what the check *cannot* do, because that shaped
everything about what it does.

## The short version

| | Signal | Detectable from CI? | Status here |
|---|---|---|---|
| Images | C2PA Content Credentials | Yes — cryptographic, offline, no key | **Enforced** |
| Text | Statistical watermark (SynthID-style) | No — needs the vendor's key | Dormant seam |
| Text | Heuristic classifier | Yes, for money | Deliberately not wired |

## Images: C2PA Content Credentials

Generative image tools sign their output. Claude, DALL·E, Imagen, Firefly and
others attach a [C2PA](https://c2pa.org/) manifest — a cryptographically signed
record of how the file came to exist — and mark it with an IPTC
`digitalSourceType` of `trainedAlgorithmicMedia`. That is a hard signal: no
model, no threshold, no probability. Either the manifest says a machine
generated the pixels or it does not.

The check scans image sources for that marker and fails on any hit that is not
allowlisted. Three IPTC values count, and all three end in `algorithmicMedia`,
so one case-insensitive pattern covers them:

- `algorithmicMedia` — purely machine-generated
- `trainedAlgorithmicMedia` — generated by a trained model
- `compositeWithTrainedAlgorithmicMedia` — composite including model output

`algorithmicallyEnhanced` deliberately does **not** count. That is denoise and
upscale applied to a real capture, and flagging it would flag half the
conference photos on the site.

### How it reads the manifest

A C2PA manifest is CBOR inside a JUMBF box tree — an APP11 segment in JPEG, a
`caBX` chunk in PNG, a RIFF chunk in WebP. CBOR stores text strings verbatim
rather than compressed, so the assertion values sit in the file as literal,
greppable bytes. The check byte-scans for them, which needs no CBOR parser and
is container-agnostic for free.

If `c2patool` happens to be on `PATH`, the check prefers it and uses its output
instead, because it validates the signing chain rather than pattern-matching
bytes. It is **not** pinned in `tools.mk` on purpose: the byte scan is the
contract, and making `make test` depend on a Rust binary would buy accuracy the
check does not rest on. Install it if you want the stronger read:

```bash
cargo install c2patool     # or: brew install c2patool
```

### Why source files, not the build

Hugo's image pipeline (`layouts/partials/functions/responsive-image.html`)
resizes everything into a WebP srcset, and that strips metadata. A C2PA manifest
in `static/uploads/` leaves no trace in `public/`. A check that scanned the build
output would pass everything and catch nothing, so this one runs on what is
committed.

### When it fires

In order of preference:

1. **Replace the image.** A generated illustration is decoration nobody made.
2. **Allowlist it,** if the generated image is the *subject* of the post rather
   than decoration for it — a write-up about a model's failure modes needs to
   show the failure. Add the path to `scripts/ai-provenance-allowlist.txt` with
   a comment naming what generated it and why it belongs.

## Text: why there is no detector here

Claude watermarks its text output. The technique biases word choice using a
cryptographic key, so the text reads identically but the sequence can be checked
against what the key would have produced. It is real, and it is unreadable from
here, for two independent reasons.

**Detection is key-gated, by construction.** A watermark detector needs the key
that generated the mark. Anthropic's [detection
API](https://www.anthropic.com/news/claude-text-watermark) is in private preview,
scoped to organisations with EU AI Act obligations: regulators, law enforcement,
media, fact-checkers, researchers, educators, and enterprises with their own
compliance duties. No endpoint, shape, pricing or rate limit is published. A
personal blog does not qualify. Google's SynthID-Text is open source, but
[detection still requires the generating
configuration](https://ai.google.dev/responsible/docs/safeguards/synthid) — it
reads Google's output and nothing else. There is no cross-vendor key registry,
so there is no tool at any price that reads Claude's text watermark from CI.

**It would be the wrong gate anyway.** Anthropic states detection is unreliable
on short text, fact-dense text, code, and anything paraphrased or substantially
edited after generation — which describes a hand-edited blog post precisely. And
a positive result means only that Claude *may have been involved*, which in this
repo is true by design: `.claude/skills/blogmentation`, `the-unwind` and
`/capture` all draft with Claude. A gate that fires on the intended workflow is a
gate that gets switched off.

So the check does not pretend. It delegates.

### The `WATERMARK_DETECT_CMD` seam

Set `WATERMARK_DETECT_CMD` to a command and the text half switches on. It is
called once per published markdown file:

```
$WATERMARK_DETECT_CMD <path-to-file>
```

and must exit:

| Exit | Meaning |
|---|---|
| `0` | no watermark found |
| `10` | watermark found |
| anything else | detector error — **fails the check** |

An unexpected exit code is a failure rather than a pass, because a broken
detector that reads as "clean" is worse than no detector at all.

This is a command rather than a baked-in HTTP call for the reason above: no
vendor has published a detection API shape to code against, so there is nothing
honest to hardcode. When access does land, the adapter is a few lines — read the
file, call the endpoint, map the verdict onto those exit codes — and nothing in
`check-ai-provenance.sh` changes.

The same seam takes any other detector, including a heuristic classifier, if you
decide you want one.

### Disclosure beats detection

A watermark hit is not automatically a failure. The rule is disclosure, not
abstinence: a post that declares `aiAssisted` in its frontmatter passes with its
hit recorded, and an undeclared one fails.

```yaml
aiAssisted:
  - draft
```

The key is free-form — `draft`, `research`, `images`, `translation` — and is
declared as `widget: hidden` on all three CMS collections so Sveltia does not
drop it on save (see [sveltia-cms.md](sveltia-cms.md)). Drafts are skipped
entirely; the gate is about what publishes.

## Heuristic classifiers: deliberately not wired in

GPTZero, Originality.ai and Pangram classify text as AI-written without any
watermark. Their false-positive rates have genuinely improved — Pangram reports
~0.01% on long passages, and the independent numbers broadly agree.

They are still not wired in here, because the same research shows [~13% of AI
text goes undetected once it imitates a specific author's
voice](https://epoch.ai/data-insights/ai-detectors-false-negatives). Writing in
Kemal's voice is exactly what `.claude/skills/kemal-voice/SKILL.md` exists to do.
A paid merge gate whose blind spot is this repo's actual risk case is friction
without cover.

The prose pipeline already covers this ground better, and advisedly stays
advisory: [REVIEW.md](../REVIEW.md), the `kemal-voice` skill, Vale's `Slop`
rules, and `/prose-review`. Those catch AI-*flavoured* prose, which is the thing
worth catching, whoever typed it.

If you change your mind, point `WATERMARK_DETECT_CMD` at a classifier. The exit
contract is the same.

## Making it block

The check fails `make test`, which runs in the `lint.yml` workflow. For that to
actually prevent a merge, `lint` must be a required status check in the `master`
ruleset — the script exiting 1 blocks nothing on its own if the job is advisory.
